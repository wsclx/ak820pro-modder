## 2. Two board families: the key finding

Community tools and two MIT forks of this repo (`0x5k/ak820pro-modder`,
`allshouldbeready/ak820-pro-macos`) show at least two AK820 Pro firmware /
interface families:

| | Family A (Mario's ISO-DE, fw 1.07) | Family B (e.g. ANSI fw 1.14, `bcdDevice 0x0114`) |
|---|---|---|
| Control | `0xFF68`, `0xAA`-framed 64-byte output reports (web driver) | `0xFF13` 64-byte **feature** reports, `0x04`-framed (`04 18` start … `04 02` save / `04 F0` finish) |
| TFT data | `0xFF67`, cmd 80, 4104-byte reports (our path) | `0xFF68`, 4096-byte output reports + ACK per chunk |
| Status here | supported | 🔶 supported via `legacy*.rs` (adamauthor #12 + fork, vespovios); needs a hardware test of this branch |

Consequences:

- 🔶 **Support family B.** `open_control` routes boards with `0xFF13` and
  no `0xFF67` to the feature-report transport (`legacy.rs`,
  `legacy_tft.rs`, `legacy_rgb.rs`) instead of refusing them. Lighting,
  per-key RGB, clock, sleep, battery and confirmed TFT uploads; no
  auto-apply, TFT restore or streaming there (lighting writes survive a
  power-off, image uploads replace the stored animation).
  Ported from adamauthor (#12 and his fork) and vespovios, behind
  per-method protocol checks rather than a `Transport` trait. See
  `docs/MACOS-800A.md`.
- 🔶 **TFT issues #1 / #2.** Sprint 1 added ack-or-pace flow control
  and an upload report; needs a hardware test. Every hardware-confirmed TFT uploader found
  (0x5k, agustinhopneto, anthonymolinam, nurlanjalil, KORTY) uses the
  family-B transport with per-chunk ACK + explicit commit. Whether
  Mario's family-A board also accepts it is unknown; check whether
  `ak820 list` shows a `0xFF13` interface on it. Either way, our cmd-80
  path sends chunks without waiting for the cmd-65 ACK
  (`device.rs` `upload_tft_animation`), which is the most likely cause of
  the noise lines.
- ✅ **Fn + Delete** (documented in the TFT view) toggles the stock clock page vs. the user GIF on
  stock firmware (0x5k, KORTY). Explains "upload ok but default animation
  stays" and should be documented in the TFT view.
- 🔶 **`SET_TFT_BUILT_IN_INDEX` (0x51) times out on PID 0x8009** (0x5k).
  The app's Factory-Default button now sends it on the control interface
  like the CLI (it used the TFT interface before); whether family-A
  firmware honours it still needs a hardware test.
- 🔶 **RTC sync** implemented via cmd 52 for family A (Sprint 1, needs a
  hardware test); the family-B transaction is documented. **RTC sync is decoded** (`04 18` → `04 28` → `00 01 5A YY MM DD hh mm ss … AA 55` → `04 02`;
  byte meanings differ slightly between tools). Fills the empty
  `commands/clock.rs` and gives a correct stock clock without rendering frames.
- 🔶 **`TftMemory` re-upload after every `set_*`**: now debounced (750 ms)
  and cached (Sprint 1). Still to decide on hardware whether it's needed at all. (incl. every paint
  stroke, re-decoding cached GIF bytes each time). Likely an artefact of
  the missing commit step; re-test after the transport fix and remove if
  so. The chunk-header constant `0x0650` (= `0x650000 / 4096`) looks like
  an SPI-flash sector address, so needless re-uploads probably also cost
  flash wear (unverified).
- ✅ Concurrent TFT uploads serialised through `src-tauri/src/tft_io.rs`.

## 3. Backend performance & robustness

- 🔲 **Sync Tauri commands run on the main thread** (Tauri docs:
  "Commands without the async keyword are executed on the main thread").
  HANDOFF §6.3 claims a worker pool; that's wrong.
  - `probe_device` (polled every 4 s) does a full `HidApi::new()` enumeration.
  - ✅ `list_tft_presets` rendered all 12 animations to compute metadata
    (**~130 ms release / ~500 ms debug**); now cached and async.
- 🔲 **Blocking HID I/O inside async tasks.** `ConnState::with` runs the
  closure on a Tokio worker (up to 500 ms per chunk on timeout). Use
  `Mutex::lock_owned()` + `spawn_blocking`.
- 🔲 **hidapi usage.** `HidApi::new()` runs twice per connect; use
  `new_without_enumerate()` + `add_devices(VENDOR_ID, 0)`. macOS opens
  devices **exclusively** by default (why CLI and app can't coexist):
  `set_open_exclusive(false)`.
- 🔲 **No flow control / response matching.** `set_many_at` discards ACKs
  and silently waits 500 ms per missing one; `read_response` matches on
  cmd only, not address, so a late ACK can satisfy the wrong chunk.
- 🔲 **`GameMode::serialize` zeroes unknown bytes** (`system.rs`). Keep the
  raw 56 bytes and patch known fields.
- 🔲 **Stringly-typed errors.** `AppError` has one variant; stale-handle
  detection matches `"HID error"`, which matches everything. Typed variants
  would also let the UI show a proper "disconnected" state.
- 🔲 **Deployment target.** `minimumSystemVersion: 11.0`, but ScreenCaptureKit
  audio is linked unconditionally and the Swift rpath depends on the
  *build host's* macOS. Set 13.0 or make audio a Cargo feature.
- ✅ `PRODUCT_IDS` no longer includes the bootloader PID `0x7140`, so no
  connection path sends control frames to a board in ISP mode.
- 🔲 Audio Spectrum maps columns by `slot % 16`; use real layout positions.
  Experiment: dirty-chunk writes for `SET_CUSTOM_LED_DATA` (each LED entry
  carries its own id, chunks are addressed) for #3.
- 🔲 TFT images are quantised without dithering (banding); GIF frame cap is
  hard-coded 30 instead of `tft_max_frames`; RGB565 conversion exists 3×;
  the Swift rpath build script exists 3×.
- 🔲 Security hardening: `csp: null` although the UI can trigger shell
  automations; iCloud pull can silently bind shell automations to hotkeys
  (confirm on pull); automations have no timeout.
- 🔲 `device.rs` has no tests beyond endpoint selection; a `Transport`
  trait + mock device would make chunking/ACK logic testable.

## 4. Frontend

- 🔲 **Lighting never reads the device** (`GET_LED_EFFECT` unused). After a
  tab switch, one slider move sends the hard-coded default (static
  `7C5CFF`) to the keyboard (`Lighting.tsx`).
- 🔲 Drafts (Keymap, Macros, Paint) are lost on tab switch without warning;
  macro names are never persisted although the UI says so.
- 🔲 Fn layer can get stuck loading (`Keymap.tsx` effect deps); automation
  markers are bound before Save and can't be unbound in the UI; pending
  paint writes outlive the view; recorder floods on key repeat and misses
  `IntlBackslash`; partial secondary-colour hex is sent.
- 🔲 **Keyboard surface implemented twice** (Keymap vs. CustomLightingPaint).
  Paint still detects the nav column by German labels → wrong on
  ANSI/UK/ES/FR. Layout-specific strings live outside `src/data/layouts`
  (breaks HANDOFF §6.9b).
- 🔲 ~45 untyped `invoke("…")` calls and duplicated backend types →
  tauri-specta or ts-rs.
- 🔲 No ESLint (would have caught the `${e}` bugs and the stale effect).
- 🔲 Stale UI: knob "coming soon" (firmware-fixed), fake TFT placeholder,
  "Next iteration" card in the TFT view, "v0.7 placeholder" texts.
- 🔲 A11y: hidden focus on Toggle / slider, no `aria-pressed` on selections,
  modals without Escape/focus trap, light-mode raw palette colours.
